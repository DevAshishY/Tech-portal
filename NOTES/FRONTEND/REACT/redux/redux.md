
**Six words to remember:** **Store → Slice → Action → Reducer → Dispatch → Selector**

---

## Part A — Basics

### RX-1. What is Redux?

A library for **centralised, predictable state management** of shared app data.

**Real-life:** a bank. Your money (state) lives in one place; you change it only by submitting a slip (action), and the clerk follows fixed rules (reducer).

```text
                 Redux Store
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
       User         Cart       Products
```

🎯 **Interview:** "Redux keeps shared state in one store with one-way data flow, so every change is predictable and traceable."

### RX-2. Why use Redux? (Prop drilling)

Without Redux, deep components get data passed through many layers that don't use it.

**Real-life:** passing a note through 5 classmates to reach one friend.

```text
❌ App → Dashboard → Header → UserProfile → Button   (props passed down every level)

✅      Redux Store
        /        \
     Header    Button   (any component reads directly)
```

**Benefits:** no prop drilling, one source of truth, predictable updates, easy debugging (DevTools).

### RX-3. What is Redux Toolkit (RTK)?

The **official, recommended way** to write Redux today. It removes boilerplate (no hand-written action types, switch statements or spread updates).

**Real-life:** old Redux = building furniture from raw wood. RTK = flat-pack furniture with instructions.

```bash
npm install @reduxjs/toolkit react-redux
```

| Old Redux | RTK |
|---|---|
| `createStore` + manual setup | `configureStore` (DevTools + thunk built in) |
| action types + action creators by hand | auto-generated by `createSlice` |
| `switch` reducers + spread copies | `createSlice` + Immer |
| extra libs for async/data | `createAsyncThunk`, RTK Query built in |

⚠️ Plain `createStore` is deprecated; say "RTK" in interviews.

### RX-4. What are the 6 core concepts?

| Concept | Meaning | Real-life (bank) |
|---|---|---|
| **Store** | where state lives | the bank vault |
| **Slice** | state + reducers + actions for one feature | one department (loans, savings) |
| **Action** | **what** happened | the deposit slip |
| **Reducer** | **how** state changes | the clerk's rule book |
| **Dispatch** | **sends** an action | handing the slip to the clerk |
| **Selector** | **reads** state | checking your passbook |

**Memory trick:** Action = WHAT, Reducer = HOW, Dispatch = SEND, Selector = READ.

### RX-5. What is the Redux data flow? ⭐

```text
User clicks button
       ↓
dispatch(increment())
       ↓
Action { type: "counter/increment" }
       ↓
Reducer: state.count += 1
       ↓
Store updated (count: 1)
       ↓
useSelector() notices the change
       ↓
Component re-renders → UI shows 1
```

**Real-life:** order at a restaurant → kitchen cooks by recipe → food on the counter → waiter brings it to your table.

🎯 **Interview:** draw this flow; it's the single most asked Redux question.

## Part B — Building Blocks

### RX-6. What is the Store?

The **single object** holding all Redux state.

**Real-life:** the bank vault; every department keeps its section inside it.

```js
// store.js
import { configureStore } from "@reduxjs/toolkit";
import counterReducer from "./counterSlice";

export const store = configureStore({
  reducer: {
    counter: counterReducer, // state.counter
  },
});
```

```text
Store
 ├── counter
 ├── user
 └── cart
```

`configureStore` automatically adds **Redux DevTools**, **thunk** and dev safety checks.

🎯 An app usually has **one** store.

### RX-7. What is a Slice?

**One feature's state + reducers + auto-generated actions.**

**Real-life:** one department in the bank, with its own records and rules.

```js
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: { count: 0 },
  reducers: {
    increment: (state) => { state.count += 1; },
    decrement: (state) => { state.count -= 1; },
  },
});

export const { increment, decrement } = counterSlice.actions; // actions
export default counterSlice.reducer;                          // reducer
```

> **Slice = State + Reducers + Actions**

### RX-8. What is an Action?

A plain object describing **what happened**. `type` is required.

**Real-life:** a deposit slip: it says *what* you want done.

```js
increment();      // { type: "counter/increment", payload: undefined }
setCount(10);     // { type: "counter/setCount", payload: 10 }
```

The `type` is `"sliceName/reducerName"`, generated by `createSlice`.

### RX-9. What is a Payload?

The **data** sent with an action.

**Real-life:** the amount written on the deposit slip.

```js
dispatch(setUser({ id: 1, name: "Ashish" }));

setUser: (state, action) => {
  state.user = action.payload; // { id: 1, name: "Ashish" }
}
```

```text
Action
 ├── type    → what happened
 └── payload → the data
```

### RX-10. What is a Reducer?

A **pure function**: `(currentState, action) → newState`.

**Real-life:** a calculator. Same input always gives the same answer, and it doesn't phone anyone.

```js
setName: (state, action) => {
  state.name = action.payload;
}
```

⚠️ Reducers must **not**: call APIs, use `Math.random()` / `Date.now()`, or have side effects. Do those in thunks or listeners.

### RX-11. How can RTK "mutate" state? (Immer)

RTK uses **Immer**: you write mutating code on a **draft**, Immer produces a new immutable object.

**Real-life:** writing on tracing paper over a document; the original stays untouched, and you get a clean new copy.

```js
// RTK (Immer)
increment: (state) => { state.count += 1; }

// What it means in plain Redux
return { ...state, count: state.count + 1 };
```

⚠️ Either **mutate the draft** or **return a new value**, never both in the same reducer.
⚠️ "Mutation" only works **inside** `createSlice` / `createReducer`, not in components.

### RX-12. What is `useSelector()`?

**Reads** a part of the store and **re-renders** the component when that part changes.

**Real-life:** checking only your own line in the passbook, not the whole bank ledger.

```js
const count = useSelector((state) => state.counter.count);
```

⚠️ Returning a **new object** each time (`state => ({ a: state.a })`) causes re-renders on every store update. Select small values, or use `createSelector` (RX-24).

### RX-13. What is `useDispatch()`?

Returns the `dispatch` function used to **send** actions.

**Real-life:** the counter window where you hand in your slip.

```js
const dispatch = useDispatch();
dispatch(increment());
```

**Memory:** `useSelector` → READ, `useDispatch` → CHANGE.

### RX-14. What is `Provider`?

Makes the store available to the whole React tree (via context).

**Real-life:** connecting every room in a building to the main water supply.

```jsx
import { Provider } from "react-redux";
import { store } from "./store";

<Provider store={store}>
  <App />
</Provider>
```

⚠️ Using `useSelector` outside `<Provider>` throws an error.

### RX-15. Show a complete working example.

```text
src/
├── store/
│   ├── store.js
│   └── counterSlice.js
├── App.jsx
└── main.jsx
```

```js
// store/counterSlice.js
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: { count: 0 },
  reducers: {
    increment: (state) => { state.count += 1; },
    decrement: (state) => { state.count -= 1; },
  },
});

export const { increment, decrement } = counterSlice.actions;
export default counterSlice.reducer;
```

```js
// store/store.js
import { configureStore } from "@reduxjs/toolkit";
import counterReducer from "./counterSlice";

export const store = configureStore({ reducer: { counter: counterReducer } });
```

```jsx
// main.jsx
import { createRoot } from "react-dom/client";
import { Provider } from "react-redux";
import App from "./App";
import { store } from "./store/store";

createRoot(document.getElementById("root")).render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

```jsx
// App.jsx
import { useSelector, useDispatch } from "react-redux";
import { increment, decrement } from "./store/counterSlice";

export default function App() {
  const count = useSelector((state) => state.counter.count);
  const dispatch = useDispatch();
  return (
    <>
      <h1>{count}</h1>
      <button onClick={() => dispatch(increment())}>+</button>
      <button onClick={() => dispatch(decrement())}>-</button>
    </>
  );
}
```

**Click `+` → flow:** `dispatch(increment())` → reducer `count += 1` → store updated → `useSelector` → re-render → shows `1`.

### RX-16. What are the 3 Redux principles?

| Principle | Meaning | Real-life |
|---|---|---|
| **Single source of truth** | all shared state in one store | one official bank ledger |
| **State is read-only** | change only by dispatching actions | you can't edit the ledger yourself |
| **Changes by pure reducers** | reducers compute new state | the clerk follows fixed rules |

```js
store.getState().counter.count = 10; // ❌ never
dispatch(setCount(10));              // ✅
```

> **One Store → Dispatch Action → Reducer changes State**

## Part C — When to Use Redux

### RX-17. When should you use Redux?

✅ **Good fit:** auth/user, cart, permissions, global filters, app config, large shared state updated from many places.

❌ **Not needed:** modal open/close, input text, hover state → `useState`.

**Real-life:** don't put your toothbrush in the bank vault.

> **Local state → `useState`. Shared/global client state → Redux. Server data → RTK Query / TanStack Query.**

🎯 **Senior answer:** "Most of what teams put in Redux is actually server data; RTK Query or TanStack Query handles that better."

### RX-18. Redux vs Context API?

| Context | Redux |
|---|---|
| passes values down (dependency injection) | real store with **selector subscriptions** |
| **every** consumer re-renders on any change | only components whose selected value changed |
| no devtools / middleware | DevTools, time-travel, middleware |
| theme, auth, locale (slow-changing) | big, frequently updated shared state |

**Real-life:** Context = a PA announcement everyone hears. Redux = personal notifications only for people who subscribed to that topic.

🎯 "Context isn't a state manager; it just passes values. Redux adds a store, selectors and tooling."

## Part D — Async: Thunk, Listener & RTK Query

### RX-19. How does Redux handle async? What is a Thunk?

Reducers must be pure, so async work (API calls) goes in **middleware**. A **thunk** is a function you dispatch instead of an action; it can do async work and dispatch real actions.

**Real-life:** reducers are cashiers (instant, no phone calls). A thunk is an assistant who goes to the warehouse, then tells the cashier what to record.

```text
dispatch(getUser())
    ↓
API call (thunk)
    ↓
pending → fulfilled / rejected
    ↓
reducer updates store → UI
```

🎯 `configureStore` includes thunk **by default**.

### RX-20. What is `createAsyncThunk`?

Creates a thunk that automatically dispatches **`pending` / `fulfilled` / `rejected`** actions.

**Real-life:** a parcel tracker: "dispatched", "delivered" or "failed", updated for you.

```js
import { createAsyncThunk, createSlice } from "@reduxjs/toolkit";

export const getUser = createAsyncThunk(
  "user/getUser",
  async (id, { rejectWithValue }) => {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) return rejectWithValue("User not found"); // fetch doesn't throw on 404
    return res.json();                                     // becomes action.payload
  }
);

const userSlice = createSlice({
  name: "user",
  initialState: { user: null, loading: false, error: null },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(getUser.pending, (state) => {
        state.loading = true;
        state.error = null;
      })
      .addCase(getUser.fulfilled, (state, action) => {
        state.loading = false;
        state.user = action.payload;
      })
      .addCase(getUser.rejected, (state, action) => {
        state.loading = false;
        state.error = action.payload ?? action.error.message;
      });
  },
});

// component
dispatch(getUser(1));
```

- `reducers` → actions **this** slice creates.
- `extraReducers` → reacts to actions created **elsewhere** (thunks, other slices).

⚠️ `fetch` doesn't reject on 404/500, so check `res.ok` and use `rejectWithValue`.

### RX-21. Thunk vs Saga vs Listener middleware?

| | Thunk | Saga | Listener (`createListenerMiddleware`) |
|---|---|---|---|
| Complexity | easy | complex (generators) | easy–medium |
| Built into RTK | ✅ | ❌ (extra package) | ✅ |
| Best for | normal API calls | complex workflows, cancellation, races | "when X happens, do Y" |

**Real-life:** thunk = a one-off errand. Saga = a project manager running a long workflow. Listener = a motion sensor that reacts when someone walks by.

```js
import { createListenerMiddleware } from "@reduxjs/toolkit";

const listener = createListenerMiddleware();
listener.startListening({
  actionCreator: todoAdded,
  effect: async (action, listenerApi) => {
    console.log("Added:", action.payload); // e.g. analytics, save draft
  },
});

configureStore({
  reducer,
  middleware: (getDefault) => getDefault().prepend(listener.middleware),
});
```

🎯 "Thunks for most API calls; the listener middleware is RTK's lighter built-in alternative to Saga; Saga only for very complex orchestration."

### RX-22. What is RTK Query? ⭐

RTK's built-in **data fetching + caching** layer. It generates hooks and handles loading, errors, caching, dedup and refetching.

**Real-life:** a smart fridge that tracks what's inside, reorders when it runs out, and tells you when it's restocking.

```js
// apiSlice.js
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

export const apiSlice = createApi({
  reducerPath: "api",
  baseQuery: fetchBaseQuery({ baseUrl: "/api" }),
  tagTypes: ["Post"],
  endpoints: (builder) => ({
    getPosts: builder.query({
      query: () => "/posts",
      providesTags: ["Post"],        // "this data is Post data"
    }),
    addPost: builder.mutation({
      query: (newPost) => ({ url: "/posts", method: "POST", body: newPost }),
      invalidatesTags: ["Post"],     // "Post data is stale → refetch"
    }),
  }),
});

export const { useGetPostsQuery, useAddPostMutation } = apiSlice;
```

```js
// store.js
export const store = configureStore({
  reducer: { [apiSlice.reducerPath]: apiSlice.reducer },
  middleware: (getDefault) => getDefault().concat(apiSlice.middleware),
});
```

```jsx
// component
const { data, isLoading, error } = useGetPostsQuery();
const [addPost, { isLoading: saving }] = useAddPostMutation();
await addPost({ title: "Hello" }).unwrap(); // unwrap() throws on error
```

| Term | Meaning |
|---|---|
| `query` | **READ** (GET), cached |
| `mutation` | **WRITE** (POST/PUT/PATCH/DELETE) |
| `providesTags` | labels cached data |
| `invalidatesTags` | marks labels stale → auto refetch |

⚠️ Forgetting `apiSlice.middleware` breaks caching, polling and invalidation.

### RX-23. RTK Query vs `createAsyncThunk`? (and vs TanStack Query)

| | `createAsyncThunk` | RTK Query |
|---|---|---|
| Loading/error state | you write it | automatic |
| Caching & dedup | ❌ manual | ✅ |
| Auto refetch after writes | ❌ | ✅ tags |
| Best for | one-off async logic, complex flows | **server data** (CRUD APIs) |

**Real-life:** `createAsyncThunk` = cooking every meal yourself. RTK Query = a meal service that also remembers what you ordered.

🎯 "If you already use Redux, pick **RTK Query** for server data. If you don't use Redux, **TanStack Query** does the same job without a store."

## Part E — Advanced RTK

### RX-24. What is `createSelector` (memoised selectors)?

Caches derived data; recomputes **only when its inputs change**.

**Real-life:** saving your bill total; you only re-add it when an item changes, not when the weather changes.

```js
import { createSelector } from "@reduxjs/toolkit";

const selectItems = (state) => state.cart.items;

export const selectTotal = createSelector(
  [selectItems],
  (items) => items.reduce((sum, i) => sum + i.price, 0)
);

const total = useSelector(selectTotal);
```

```text
Inputs changed?  No → return cached result
                 Yes → recompute
```

Use for totals, filtered/sorted/grouped lists.

⚠️ Without it, `useSelector((s) => s.todos.filter(...))` returns a **new array** every store update → needless re-renders.

> **Selector = READ, createSelector = READ + CACHE**

### RX-25. What is `createEntityAdapter`?

**Normalises** lists into `ids` + `entities` (like a database table) and generates CRUD reducers and selectors.

**Real-life:** a library catalogue: look up a book by its number instantly instead of scanning every shelf.

```js
import { createEntityAdapter, createSlice } from "@reduxjs/toolkit";

const usersAdapter = createEntityAdapter();

const usersSlice = createSlice({
  name: "users",
  initialState: usersAdapter.getInitialState(),
  reducers: {
    userAdded: usersAdapter.addOne,
    userUpdated: usersAdapter.updateOne, // payload: { id, changes: {...} }
    userRemoved: usersAdapter.removeOne,
  },
});

export const usersSelectors = usersAdapter.getSelectors((state) => state.users);
usersSelectors.selectById(state, 1);
usersSelectors.selectAll(state);
```

```text
state.users
 ├── ids:      [1, 2, 3]
 └── entities: { 1: {...}, 2: {...}, 3: {...} }
```

🎯 "Normalised state = O(1) lookup by ID, no duplicated data, easy updates."

### RX-26. What is Redux middleware?

Code between `dispatch()` and the reducer. It can log, delay, modify or stop actions.

**Real-life:** airport security between check-in and the plane.

```text
dispatch(action) → Middleware (log / async / block) → Reducer → New State
```

```js
const logger = (store) => (next) => (action) => {
  console.log("dispatching", action);
  const result = next(action);           // pass to next middleware / reducer
  console.log("next state", store.getState());
  return result;
};

configureStore({
  reducer,
  middleware: (getDefault) => getDefault().concat(logger),
});
```

🎯 Shape: `store => next => action`. Thunk, listener and RTK Query are **all** middleware.

⚠️ Use `getDefault().concat(...)`; passing a plain array removes thunk and the safety checks.

### RX-27. How do you use TypeScript with RTK?

Define two types once, then make pre-typed hooks.

```ts
// store.ts
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

```ts
// hooks.ts
import { useDispatch, useSelector } from "react-redux";
import type { RootState, AppDispatch } from "./store";

export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();
```

```ts
// typed payload
import { createSlice, PayloadAction } from "@reduxjs/toolkit";

setName: (state, action: PayloadAction<string>) => {
  state.name = action.payload;
}
```

**Real-life:** labelled drawers: you can't put socks in the cutlery drawer.

> **RootState** = store shape, **AppDispatch** = dispatch type (knows thunks), **PayloadAction\<T\>** = payload type.

⚠️ Plain `useDispatch()` doesn't know about thunks, so TS complains when you dispatch one. Use `useAppDispatch`.

### RX-28. What is the `serializableCheck` warning? ⚠️

`configureStore` warns when **non-serializable** values enter state or actions: Dates, Promises, class instances, functions, File/Blob.

**Real-life:** you can't fax a cake; only paper (plain data) goes through.

**Why it matters:** breaks DevTools time-travel and persistence.

```js
// store a string, not a Date object
state.createdAt = new Date().toISOString(); // ✅

// if truly unavoidable, ignore narrowly
middleware: (getDefault) =>
  getDefault({ serializableCheck: { ignoredActions: ["upload/setFile"] } }),
```

🎯 "Redux state must be plain, serializable data." Never disable the check globally.

### RX-29. What is `redux-persist`?

Saves Redux state to storage (`localStorage` / `AsyncStorage`) and restores it after reload.

**Real-life:** saving a game so you continue from the same level next time.

```js
import { persistStore, persistReducer, FLUSH, REHYDRATE, PAUSE, PERSIST, PURGE, REGISTER } from "redux-persist";
import storage from "redux-persist/lib/storage";
import { combineReducers, configureStore } from "@reduxjs/toolkit";

const persistConfig = { key: "root", storage, whitelist: ["cart"] }; // persist only cart
const rootReducer = combineReducers({ cart: cartReducer, user: userReducer });

export const store = configureStore({
  reducer: persistReducer(persistConfig, rootReducer),
  middleware: (getDefault) =>
    getDefault({
      serializableCheck: { ignoredActions: [FLUSH, REHYDRATE, PAUSE, PERSIST, PURGE, REGISTER] },
    }),
});

export const persistor = persistStore(store);
```

```jsx
<Provider store={store}>
  <PersistGate loading={null} persistor={persistor}>
    <App />
  </PersistGate>
</Provider>
```

⚠️ Ignore redux-persist's own actions, or you get serializable warnings.
⚠️ Use `whitelist` / `blacklist`; never persist tokens or sensitive data in `localStorage`.

## Part F — Legacy & History

### RX-30. What is `connect()`?

The **old HOC** way to link a component to the store (before hooks).

**Real-life:** an old landline with a separate handset and cable, vs a mobile phone (hooks).

```js
export default connect(mapStateToProps, mapDispatchToProps)(Counter);
```

### RX-31. What are `mapStateToProps` and `mapDispatchToProps`?

```js
const mapStateToProps = (state) => ({
  count: state.counter.count,   // store → props
});

const mapDispatchToProps = {
  increment,                    // actions → props (auto-dispatched)
};

function Counter({ count, increment }) {
  return <button onClick={increment}>{count}</button>;
}
```

- `mapStateToProps` = **READ** state as props.
- `mapDispatchToProps` = **SEND** actions as props.

### RX-32. `connect()` vs hooks?

| Old (`connect`) | Modern (hooks) |
|---|---|
| `mapStateToProps` | `useSelector()` |
| `mapDispatchToProps` | `useDispatch()` |
| HOC wrapper | direct hooks |
| class components | function components |

🎯 "`connect()` is the older HOC approach; modern apps use `useSelector` and `useDispatch`. You'll still see `connect` in legacy code."

### RX-33. What is Flux?

An **architecture pattern** with one-way data flow (by Facebook).

**Real-life:** a one-way street: traffic only moves in one direction, so it's easy to follow.

```text
Action → Dispatcher → Store(s) → View
```

Redux was **inspired by** Flux but simplified it.

### RX-34. Redux vs Flux?

| Redux | Flux |
|---|---|
| library | architecture pattern |
| one store | many stores |
| no dispatcher (store dispatches) | central Dispatcher |
| pure reducers change state | stores change their own state |

### RX-35. What does Redux DevTools give you?

See every action, state before/after, diffs, action history and **time-travel** (jump back to an earlier state).

**Real-life:** CCTV with a rewind button for your app's state.

```text
Initial → increment → count: 1 → increment → count: 2   (click any step to jump back)
```

🎯 Works automatically with `configureStore`.

### RX-37. Common Redux mistakes

| ❌ Don't | ✅ Do |
|---|---|
| put every piece of state in Redux | local UI state in `useState` |
| API calls inside reducers | thunks, listener, RTK Query |
| mutate state outside `createSlice` | dispatch actions |
| mutate the draft **and** return a value | do one or the other |
| `useSelector` returning new objects/arrays | select primitives or `createSelector` |
| store Dates, Promises, class instances | plain serializable data |
| hand-write loading/error for every API | RTK Query |
| `middleware: [logger]` (replaces defaults) | `getDefault().concat(logger)` |
| forget `apiSlice.middleware` | add it to the store |
| ignore `res.ok` in thunks | check it + `rejectWithValue` |
| store lists as big arrays and `find()` by ID | `createEntityAdapter` |

### RX-38. 2-minute revision 🚀

```text
Redux = central store
Slice = state + reducers + actions
Action = WHAT       Reducer = HOW
Dispatch = SEND     Selector = READ
createSelector = READ + CACHE
Thunk = async/API logic
RTK Query = fetch + cache + hooks, automatic
```

```js
const count = useSelector((state) => state.counter.count); // READ
dispatch(increment());                                       // SEND
const { data, isLoading } = useGetPostsQuery();              // FETCH
```

```text
User → dispatch() → Action → Reducer → Store → useSelector() → UI
```

### RX-39. What should you build to practise?

**Redux Todo App:**

```text
├── Add / delete / toggle todo     → createSlice, payload, reducers
├── Filter todos (all/done/active)  → createSelector
├── Fetch todos from API            → createAsyncThunk + extraReducers (loading, error)
├── Same fetch with RTK Query       → createApi, useGetTodosQuery, tags
├── Store todos by ID               → createEntityAdapter
└── Keep todos after refresh        → redux-persist
```

🎯 In interviews, say you built it **both** ways (thunk and RTK Query) and explain why RTK Query wins for server data.
